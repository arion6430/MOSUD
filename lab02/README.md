# lab02. Множества и мультимножества в SQL

**Вариант 5:** штат X = GO, штат Y = DF.
A = product_id товаров, купленных клиентами штата GO (заказы delivered).
B = product_id товаров, купленных клиентами штата DF (заказы delivered).

| Величина | Значение |
|---|---|
| \|A\| (все строки, с повторами) | 2 277 |
| \|A\| (различных product_id) | 1 650 |
| \|B\| (все строки, с повторами) | 2 355 |
| \|B\| (различных product_id) | 1 764 |
| A ∪ B (UNION) | 3 130 |
| A ∪ B (UNION ALL) | 4 632 |
| A ∩ B (INTERSECT) | 284 |
| A − B (EXCEPT) | 1 366 |
| B − A (EXCEPT) | 1 480 |

**Вывод о дубликатах.** UNION ALL (4 632) больше UNION (3 130), потому
что суммирует все строки A и B без удаления повторов: и внутри каждого
множества (один и тот же товар мог быть куплен несколько раз), и на
пересечении (товары A∩B считаются дважды). То же видно в пункте 8
lab02.sql: запрос пересечения без DISTINCT даёт 606 строк вместо 284 —
SQL-таблица по умолчанию ведёт себя как мультимножество, и только явные
DISTINCT/UNION/INTERSECT/EXCEPT (без ALL) превращают результат в
множество.

Объединение и пересечение коммутативны на данных (симметрическая
разность (A∪B) и (B∪A), а также (A∩B) и (B∩A) пустая — union_diff = 0,
intersect_diff = 0). Разность некоммутативна: |A−B| = 1 366 ≠
|B−A| = 1 480.
