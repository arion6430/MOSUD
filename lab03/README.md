# lab03. Выборка, проекция, переименование и реляционная алгебра

**Вариант 5.** Отношение — `order_payments`. Предикат —
`payment_type = 'credit_card' AND payment_installments >= 6`. Проекция —
`order_id, payment_installments, payment_value`.

**Реляционное выражение:**

```
π_{order_id, payment_installments, payment_value} (
    σ_{payment_type = 'credit_card' ∧ payment_installments ≥ 6} (order_payments)
)
```

Исходный запрос (σ, затем π) и его вариант с предикатом, разбитым на
две последовательные выборки (σ по `payment_type`, затем σ по
`payment_installments`), дают одинаковое число строк — **16 127** —
что подтверждает эквивалентность: выборка коммутативна, и сложный
предикат можно как разбивать на цепочку фильтров, так и вычислять
одним составным условием. Вариант, где проекция выполняется раньше (на
промежуточном отношении `narrowed` сразу отбрасывается лишний столбец
`payment_sequential`), возвращает тот же результат — 16 127 строк, то
есть порядок σ и π в данном случае на результат не влияет, хотя влияет
на то, сколько «лишних» столбцов проходит через промежуточные шаги.

Дубликаты в проекции возможны: `SELECT` без `DISTINCT` возвращает все
16 127 строк, а число различных кортежей `(order_id,
payment_installments, payment_value)` — 16 124, то есть 3 строки
совпадают по всем трём проецируемым атрибутам (это разные записи
исходного отношения, различающиеся только `payment_sequential`,
который не входит в проекцию). Математическая проекция по определению
работает с множеством и не может дать различное число элементов при
одинаковом наборе кортежей, а `SELECT` в SQL — операция над
мультимножеством и сохраняет такие совпадения; только `SELECT DISTINCT`
устраняет их и даёт 16 124 строки.
